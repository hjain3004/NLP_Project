## Design as built

Protocol follows the coordinator's frozen amendment: every binding check, merge attempt and gate rerun happens in a
detached worktree while the task is still `integration_ready`.

1. **Reconcile** any task in `integrating` against actual Git (below).
2. **Select**: `integration_ready` tasks whose dependencies are all `completed` and that are not parked, ordered by
   `(contract integration_order, topological index over the dependencies table, task_id)`. `integrate <id>` proceeds only if `<id>` is that head, else exits 1 naming the head (`not_queue_head`). No-arg picks the head.
3. **Verify** (each failure = exit 1, a named `reason_code`, a recorded event plus `integration-rejection` artifact, no ref movement, not completed). Recomputed, not trusted: dependencies completed; each dependency interface hash equals `current_interface_binding` and the pinned version; semantic-lock claims unchanged; contract/context hashes; candidate commit exists, descends from base, tree hash and `git diff --binary --full-index` sha256 equal the stored binding; candidate worktree HEAD still equals the reviewed commit with no tracked changes; verification-evidence hash recomputed from its payload, bound to the same candidate binding, `passed`; a `no_blocking_findings` review row whose payload bindings (`reviewed_result_commit`, tree, diff, base, contract, context, `verification_evidence_hash`) all match; reviewer ids differ from author ids; integrator id differs from all four.
4. **Plan**: `git worktree add --detach agent-system/runtime/integration/<task>/wt-<integration_id>` at the integration head; fast-forward when head == candidate `base_commit`, else `git merge --no-ff --no-edit` of the unchanged candidate commit. Author/committer/dates are pinned from a recorded `planned_at`, so the resulting commit hash is reproducible (this is what makes crash replay exact). Conflict: `merge --abort`, reject `conflict_repair_required`. Then `candidate_patch_unchanged` is checked from Git (first parent / second parent, diff hash re-hashed) and the contract `deterministic_checks` run on the resulting tree with a per-command timeout (timeout = failure, process group killed) and a scrubbed environment (minimal PATH, throwaway HOME, no `GIT_*`, no `CLAUDE_*`/`ANTHROPIC_*`/credential variables). Hooks are disabled (`core.hooksPath=/dev/null`) for every Git call.
5. **Claim (transaction 1)**: `integration-lease` artifact (epoch, fencing token, integrator run id, expiry; mirrors `review-assignment`) + `integration-intent` artifact (old head, candidate commit, planned commit/tree, strategy, planned_at, gates, integrator id, lease id) + legal `integration_lease_issued` (`integration_ready -> integrating`). Inside the same `BEGIN IMMEDIATE` it re-checks task state, that no task is `integrating`, that the task is still the queue head, and that the branch still equals the head the plan used. A process-level `flock` also exists, but only so a live run is never "reconciled" by a second process; the guarantee is the transaction.
6. **Advance**: `git update-ref refs/heads/<branch> <planned> <old>` (all-zero old value when the branch does not exist yet, i.e. create-only).
7. **Complete (transaction 2)**: legal `integration_passed` (`integrating -> completed`) + `integration-record` artifact whose payload **is** an `integration-manifest` (exact schema fields only), written first under `agent-system/runtime/integration/<task>/records/<id>/` next to copies of the stored review verdict and implementation manifest and validated with `validate_artifact`. Intent and lease are marked consumed (`integrable = 0`).

**Branch:** default `agentctl/integration` (`--branch`, `AGENTCTL_INTEGRATION_BRANCH`). Refused if it is `main`/`master`, malformed, the repository's checked-out branch, or checked out in any worktree. It is created (by the CAS, from the zero value) at the first integrated candidate's contract `base_commit`, or `--base <rev>`; nothing creates the ref on a rejected run.

**Reconciliation** (every invocation, under the process lock, before selection): for each `integrating` task, read the intent and actual Git. Branch head equals or has the planned commit on its first-parent chain -> record `integration_reconciled` (`git_step_applied`), re-verify evidence, complete the event-store side with the idempotent key `integration-complete:<id>`; no Git step is redone. Branch still equals the intent's pre-plan head -> record `git_step_not_applied`, re-verify, replay the plan under the **same intent and lease**, require the replayed commit to equal the recorded planned commit, rerun gates, CAS, complete. Branch moved to anything else, intent or lease missing, evidence no longer verifies, or replay differs -> record `branch_moved_unrelated`/refuse `reconciliation_required`; the task stays `integrating`, so the single slot stays held and nothing else integrates (fail closed). Leftover `wt-*` worktrees of a crashed run are removed first.

**Duplicate requests:** a completed task returns `already_integrated` with the stored record and a check that the branch still contains the recorded commit (`record_git_divergence`, exit 1, otherwise). No second merge, event or record.

**Parking (my addition, to keep the queue live):** a conflict or failed affected gate is deterministic for a given (candidate, branch head). It is recorded with `retry_requires_new_evidence` and the head it was evaluated against; the task is excluded from the eligible queue and an explicit retry is refused (`retry_without_new_evidence`, AGENTS.md s9) until the branch head moves. Static-evidence rejections are not parked (they are pure functions of mutable stored state and are re-evaluated every time).

**Exit codes:** 0 integrated / already_integrated / reconciled; 1 rejected or refused; 2 usage; 3 queue empty. One JSON object on stdout.

**Rejection state effects:** only `interface_binding_stale` changes task state, via the legal `dependency_changed` (`-> stale`), which is exactly what `bump_interface` does. Every other rejection leaves the task in `integration_ready` with a `integration_rejected` event whose prior and next state are equal (the `review_rejected` pattern). Proposed follow-ups (repair / replan / review) are written into the rejection artifact; no task is auto-created.

## Demonstrated, simulated, untested

**Demonstrated** (real `git`, real `EventStore`, real `python3 -m agentctl integrate` processes; candidates built through the public scheduler/review API with a real commit in a real leased worktree and a distinct reviewer identity):
successful integration (fast-forward; tree contains the change, branch advanced, task `completed`, record schema-valid and equal to Git and events, user checkout branch unmoved, candidate worktree HEAD unchanged); second disjoint candidate merged with `--no-ff` (parents are the prior head and the unchanged candidate commit; both files present; both candidate commits reachable and tree hashes unchanged); candidate not `integration_ready` refused; amended and replaced candidate rejected with branch untouched; stale dependency rejected and queue order dependency-first even though the dependent sorts first by id; stale interface binding rejected (`replan_required`, task `stale`); merge conflict rejected with branch, candidate and worktree untouched; failing affected check (fails only on the merged tree) leaves the branch and task state unchanged and records exit codes; hanging check times out and is a recorded failure; gate environment scrub; duplicate request is a no-op (commit count, event count, record count unchanged); 4 parallel CLI processes on one task -> exactly 1 `integrated`, 3 `already_integrated`, one merge, one record, one intent; 2 parallel no-arg processes take distinct heads; integrator id equal to author session/run or reviewer session/run refused; queue order independent of creation order; explicit non-head request refused naming the head; `--branch main` / checked-out branch refused; claim transaction refuses a second concurrent integration (sequential and with racing threads); CAS refuses when another writer moves the ref after the claim.

**Simulated (label in each test name/docstring):**
- Crash instants: a real child process dies via `os._exit(97)` at `after_ref_update`, `after_intent` or `after_plan` (injected through the `fault_hook` argument of `integrate()`, which the CLI never passes). Git, SQLite and recovery are real; only the instant of death is injected. Recovery verified for all three, including no second merge commit after `after_ref_update`, and the replay reproducing the exact planned commit after `after_intent`.
- Unrelated branch movement between crash and recovery, and a concurrent writer moving the ref after the claim: real `git commit-tree` / `update-ref`, injected at a chosen point.
- `Lab.tamper` (direct SQL through `EventStore.execute` with a `simulated_fixture` event) in: forged `integration_ready` without a review, doctored candidate-binding diff hash, edited verification evidence, review bound to other evidence, reviewer id rewritten to the author id, an added dependency edge (no public API; `dispatch` would refuse to lease a task with an open dependency), a missed interface-staleness propagation, and the `integration_order` payload value (see dependency 2). These prove integration re-derives evidence; they do not claim the corruption is reachable through ordinary commands.

**Untested or not exercised:**
- Candidates produced by Lane A's `run` / `review run` (not merged here); integration of a real provider-authored candidate; the full live cycle (Task 3).
- `--base`; `lease_expired`; `record_git_divergence`; `semantic_lock_stale`/`unverifiable`; `contract_stale`/`context_stale`; `verification_evidence_failed`; `review_not_passing`; `base_incompatible`; `candidate_already_in_integration_branch`; `candidate_altered`; recovery paths that end in a stuck `integrating` task other than the unrelated-movement one (replay divergence, evidence no longer verifying); `kill -9` of a process holding the lock mid-gate; very large repositories; git versions other than the one installed here.
- Candidate commit reachability is verified as "object exists, descends from base, tree and diff hashes match, and (if the leased worktree still exists) its HEAD is the reviewed commit". If the worktree has been deleted and no ref holds the commit, a `git gc` after the prune window could remove it before integration; nothing pins it. After integration it is the merge's parent (or the branch head).
- An empty `deterministic_checks` list passes vacuously and the manifest then lists only the built-in `integration:candidate-commit-preserved` gate.

## Discovered dependencies / requests for Lane A (owner of the shared internals)

1. **Missing legal transitions (blocking operationally, not for correctness).** The pinned table has no way out of `integrating` except `integration_passed`, and no way from `integration_ready` to `repair_required`. Consequences as built: a conflicted or gate-failing candidate stays `integration_ready` (parked by artifact, not by state); and a task whose recorded intent cannot be replayed stays `integrating` forever, holding the single slot until a human acts. Requested rows (and the pinned count/test updated by the owner): `(INTEGRATION_READY,) "integration_rejected" -> (REPAIR_REQUIRED, REPLAN_REQUIRED, ESCALATED)` and `(INTEGRATING,) "integration_aborted" -> (INTEGRATION_READY, ESCALATED)`. Rationale: AGENTS.md s9 repair/escalation ladder for a failed integration gate, and recovery without a manual database edit. Once added, `record_rejection` / `reconcile` change only their `state_event`/`state_target` arguments.
2. **`integration_order` is not carried into task state.** The contract schema requires `dependencies.integration_order` but `TaskSpec`/`plan.task_spec_from_contract` drop it and `TaskSpec.from_payload(**data)` would reject an extra key. Request: add `integration_order: int | None = None` to `TaskSpec` (and `to_payload`/`from_payload`) and set it from `contract["dependencies"]["integration_order"]` in `plan.py`. Lane B already reads `payload_json["integration_order"]`, so no change is needed here once it exists. Until then the queue is effectively `(topological index, task_id)`.
3. **`scheduler.verify_candidate` runs contract checks with the full inherited environment and no timeout** (already assigned to Lane A). Visible here: with provider credentials in the session environment, a candidate's own check can read them, and my environment-scrub test had to restrict its strict assertion to the integration worktree for that reason.
4. **`LeaseManager.issue` / scheduler have no integration-lease concept.** I mint `integration-lease` as an artifact (per the amendment); `status()` therefore reports `lease_epoch` 0 for integration. No change requested unless the coordinator wants `status` to surface it.
5. **The existing `integrations` table is unused.** I kept all state in `tasks`/`artifacts`/`events` as instructed. If a later reader expects `integrations` rows, that is a change for the owner of `store.py` or an explicit decision.

## Schema proposals

None required. The manifest schema can be satisfied truthfully: `lease_id`/`lease_epoch`/`fencing_token` come from the `integration-lease` artifact; `integrator_session_id` carries the control-plane run id `integrator-run:<uuid>` (a deterministic integrator has no model session; `integrator_role` is `integrator`); `candidate_patch_unchanged` is computed from Git, not asserted; `affected_gates_rerun` carries only `gate`/`result`, and the richer per-gate evidence (exit code, timeout flag, stdout/stderr hashes, duration) lives in the `integration-intent` artifact. If a future reader needs the integrator kind or per-gate evidence inside the manifest itself, that would be a schema commitment requiring the existing approval mechanism; it is not proposed now.
